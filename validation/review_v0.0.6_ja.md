## 追加・生成した文書

C0とP01〜P39の単独入力は、プロンプト集の本文を同じ生成元から書き出し、本文の一致を検査します。各ハンズオン入力は対応Pの全文を保持し、具体値の記入と教材条件の追加を行っています。P38は共通集・単独ファイル・H04・D04の4か所で完全一致を保ちます。

## 重点修正と理由

| 指摘分類 | 例と修正 |
|---|---|
| 補足だけ | H06/P06、H09/P10、D09/P10・P26、D12/P12、D21/P27等。入力1ブロックに共通指示と教材条件を統合。 |
| 参照資料の欠落 | H06の10ケース、D06の要件、D28の監視表を本文へ収録。以後は保存した承認版を読む。 |
| 計画前の実装 | H12等の実装指示の前に実タスクの計画・人の承認を設けた。既存同一タスクは再生成しない。 |
| 工程の前提 | P06/P25、P10/P26の初回REVIEW案を扱う条件を明示。D18からS-02を計画して実行する。 |
| 操作の混在 | CIを計画するP19と実装するP12、試験計画と実行/人の記録をP18で分離。 |
| 公開の停止条件 | タグ新規作成の既存タグ拒否と、Draft作成・公開の既存タグ必須を別にした。自動Draftの二重作成も避ける。 |
| 文書状態 | P39で本文修正を限定し、新版REVIEW・過去承認保持・保存/再読込み・人の再承認を統一。 |

## 検査の限界

文書としての点検と機械的な一致/構造検査です。すべての入力をChatGPT/Codexへ送った試験、Windows/UbuntuのGUI、GitHub Actions、実リポジトリの公開は実施していません。指示文の存在は、エージェントが必ず従うことを保証しません。依存版・CLIオプション・外部URLは採用工程で再確認してください。
