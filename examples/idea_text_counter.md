## 解決すること

文章を貼り付けて、Unicodeコードポイント数、UTF-8バイト数、行数をすぐに確認する。利用者は開発者や文章のサイズを確認したい人。アプリ内で文章を保存しない。

## 代表的な操作

起動 → テキスト欄へ入力・貼付け → 3種類の数値を見る → クリア → 終了。

## 初期版

| ID | 要求 | 最低限の受入条件 |
|---|---|---|
| I-01 | 入力・貼付け | 1つの複数行入力欄を使える。アプリ独自のクリップボード操作機能は不要。 |
| I-02 | 3種類の集計 | Goの同じ集計処理を呼び、入力変更に追従して数値を更新する。 |
| I-03 | クリア | 入力と3つの数値を空／0へ戻す。以前の応答で数値が復活しない。 |
| I-04 | エラー表示 | 集計呼出しが失敗したら古い数値を最新結果として見せず、短いエラーを表示する。 |

## 計数ルール

すべての集計でCRLFとCRをLFへ統一した文字列を使用する。コードポイント数は空白・改行も含む。UTF-8バイト数はLF統一後の値。空文字列は0行。それ以外はLF数+1行で、末尾の改行の後の空行も数える。

結合文字や絵文字の組合せが1文字に見えても、複数コードポイントなら複数と数える。画面に「コードポイント数」「UTF-8バイト数（改行LF統一後）」「行数」と表示する。

## 固定条件と仮定

- ホストWindows 11。日常作業はWindowsを基本とし、既存運用でWSL2を使用する場合はその環境環境、Windows確認は別クローンでもよい。
- Go＋Wails v3.0.0-beta.25。UIは標準vanillaのHTML/CSS/JavaScript。
- Windows 11 amd64、Ubuntu 24.04/26.04 amd64で確認する。新しいLTSは追加確認する。
- GitHub ActionsでOS別にネイティブビルドする。
- Windows ZIP、Linux tar.gz。必要なOSランタイムはREADMEで案内する。
- 通常の確認入力は空〜10,000コードポイント程度。最大長制限や性能保証を未測定のまま設定しない。
- アプリが入力本文を意図的にファイル保存・ログ出力・外部送信する機能を持たない。OS、IME、WebViewの内部動作までゼロ書込み・ゼロ通信を保証する趣旨ではない。
- プロジェクトのライセンス、著作者名、公開先は未決定。学習用作業を進められるが、公開前に利用者が決める。
