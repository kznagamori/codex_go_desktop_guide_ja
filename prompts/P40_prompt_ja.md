# P40：後の工程でコピーしたテンプレートの記入欄を整理する

**ドキュメントバージョン：v0.0.9**  
**更新日：2026年10月2日**

**入力先：Codex CLI。** 各{...}を実値にして、下のブロックだけを送信します。元の共通集を別に送る必要はありません。

**送信前にユーザーが記入：** `{今回コピーしたリポジトリ内の実在パスを列挙}`、`{参照するidea・naming・仕様・計画の実在パスと版}`、`{要求／設計／タスク計画／試験計画／結果記録等}`

実行条件・省略条件は[共通集のP40](../04_prompt_templates_ja.md#p40)を確認してください。人の承認が必要な入力は、対象版の内容を実際に確認した後だけ送信します。

````markdown
# P40：後の工程でコピーしたテンプレートの記入欄を整理する

## 目的・対象

- Codex CLIで、今回コピーしたファイルだけを下の許可範囲で整えてください。初回4件の設定はP04を使うため、同じ処理を重ねません。
- 対象ファイル：{今回コピーしたリポジトリ内の実在パスを列挙}
- 根拠：{参照するidea・naming・仕様・計画の実在パスと版}
- 今回の工程：{要求／設計／タスク計画／試験計画／結果記録等}
- 作業の種類は記入欄の整理です。新しい要求、設計判断、テスト実行、承認は行いません。

## 確認と記入

- Gitルート・既存差分・適用規約を読み、コピー元とコピー先を区別します。配布資料や元templatesは編集しません。
- 対象の記入欄をファイルと欄ごとに列挙し、根拠に明記された値だけ転記します。文脈ごとに意味が違う{ID}を一括置換しません。
- 目的・対象OS・要求ID・参照パス等は指定した根拠から使用します。名前は承認済みnamingを参照し、名称を独立に変更しません。
- 今回まだ決めない内容は「未決（決める工程）」、存在しない文書・コードは「未作成」、未実施の日時・ログ・hashは「未実施」、判断対象外は「該当なし（理由）」にします。使える実値がないときに架空のコマンドやIDを作りません。
- コピーしただけのサンプル行は「未登録」と明示するか空表にし、実績にはしません。既存の履歴・FAIL・承認は消しません。
- Markdownの説明例、コードの波括弧、Go/JSON/JavaScript、GitHub Actionsの${{ ... }}、正規表現の量指定は置換対象外です。

## 版と保護

- 配布資料の版ヘッダーは使用テンプレートの由来として残し、プロジェクト文書版・状態は別に管理します。
- 新しい計画・仕様の実文書はr1・DRAFTまたはREVIEW・未承認です。承認済み本文を変える場合は対象版を確認し、新版REVIEWとして旧版への承認を履歴に残します。差分がなければ版と状態を変えません。
- 試験結果は実際の証拠だけを使用し、穴埋めのために実行や合格を作りません。
- 実行時の承認者・承認根拠、PASS・DONE、公開許可、過去の実行日時を作りません。実績の更新だけを文書全体の承認と扱いません。
- 製品コード、依存、CI、元のtemplates、GitHub、remote、commit/push/tagは変更しません。未決事項を解決する要求作成・設計は、別のP06/P10等の入力に分けます。

## 保存と終了

- 対象ファイルとdocs/workflow/template-check.mdだけを保存します。後者に欄・更新前後・根拠・未決・残した記入欄と理由を追記します。
- 再読込み・git status・差分で確認し、未追跡ファイルは全文も確認します。許可範囲外への変更があれば止めます。
- 未処理の記入欄と説明用の波括弧を区別して報告します。必須の未決事項があれば関係する次工程だけを止め、記入欄が空でないことを仕様完成の根拠にしません。
- 次の1操作を示して停止します。自動承認や次タスクの開始はせず、保存不能は未保存と明記します。
````
